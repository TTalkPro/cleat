# cleat-126 M12 收尾：GC、分配与性能全量重测

- 里程碑：M12　依赖：cleat-120 ~ 125　状态：完成（2026-10-18）
- 设计依据：[22 §7](../designs/22-gc-and-performance-followups.md)、[GC 配置实测](../notes/gc-config-and-tier0-two-machines.md)

## 工作内容
1. 本地-only 重测：按 2026-10-17 的决定不再使用 `192.168.3.111`。本机是 linux01（AMD Ryzen 7 9700X，8C / 16T）。
2. r7rs 56 项，cleat 与 OpenJDK 25 C2 各 3 轮，同窗口按基准 / 实现交错；每项取最小值。C2 路径为
   `~/.local/share/mise/installs/java/25.0.2/bin/java`。
3. 外部负载防护：排除本测量的 cleat / C2 子进程后，单进程 CPU 超过 200% 视为污染。每个 cleat / C2 数据对运行中持续采样；
   命中污染时整对丢弃，等待连续 30 秒低负载后重跑同一对。多次被 keelson 测试打断的早期数据改名为
   `results/c126-local-contaminated-*.jsonl`，只留作过程证据，不进结论。
4. `bench/r7rs/gc_bench.py` 本地复跑 GC 配置敏感性矩阵（workstation / server ± gen0 256MB）。
5. `tools/alloc.cs` 复跑 array1、gcbench、nboyer、browse、cpstak、peval、mbrotZ、string 的分配采样。
6. 更新 designs/21 / designs/22 与本任务书；官方对比默认配置继续不引入 GC 旋钮。

## 验收标准
- 几何平均与各项数字写进任务书，注明本机、JVM 与本地-only 口径。
- GC 矩阵与 8 项分配采样完成；默认配置仍不采用 Server GC / 扩大 gen0。
- 基线、门禁、全量不变；本轮不改 `src/`，无需重建种子。

## GC 配置矩阵（5 项 × 3 轮取最小）

| 配置 | array1 | gcbench | nboyer | deriv | cpstak |
|---|---:|---:|---:|---:|---:|
| cleat workstation | 14.327 | 1.205 | 7.872 | 6.499 | 12.913 |
| workstation + gen0 256MB | 10.724（-25.1%） | 1.047（-13.1%） | 8.421（+7.0%） | 7.288（+12.1%） | 14.038（+8.7%） |
| server | 8.820（-38.4%） | 1.110（-7.9%） | 5.549（-29.5%） | 6.833（+5.1%） | 13.665（+5.8%） |
| server + gen0 256MB | 5.859（-59.1%） | 1.056（-12.4%） | 6.882（-12.6%） | 7.567（+16.4%） | 14.517（+12.4%） |

JVM 对照继续证明“JVM 靠大堆”不成立：`array1` 默认 1.489 s，`-Xmx1g` 7.030 s、
`-Xmx512m` 7.862 s，GC 次数分别升至约 300 / 540；但默认配置本身最稳。Server GC 和扩大 gen0
对 `array1` 的收益会被 `deriv` / `cpstak` 的回归抵消，仍不进默认配置。

## 分配采样（GCAllocationTick）

采样有约 100 KiB 事件间隔，数字用于相对分布；trace 会拖慢耗时，不与无 trace A/B 耗时直接比较。

| 基准 | 总分配 | 主导类型 |
|---|---:|---|
| array1 | 19.36 GB | `System.Int64` 59.1%、`Object[]` 39.8% |
| gcbench | 3.61 GB | `r7rs.gcbench.ClassNode` 88.5% |
| nboyer | 7.41 GB | `PersistentList` 39.0%、`Cons` 37.3%、`Int64` 16.1% |
| browse | 6.61 GB | `MPair` 64.5%、`System.Char` 27.8%（约 1.84 GB） |
| cpstak | 75.21 GB | 四层闭包合计约 80.6%、`System.Int64` 18.6% |
| peval | 5.83 GB | `MPair` 55.3%、`ref_count` 闭包 18.0% |
| mbrotZ | 1.10 GB | `Complex` 47.3%、`System.Double` 22.8% |
| string | 10.32 GB | `System.String` 58.1%、`System.Char[]` 39.3% |

`browse` 的 `Char` 分布与 cleat-121 的 CharBox 收益一致；剩余主导仍是基准结构需要的 `MPair`。
`array1`、`cpstak`、`peval`、`mbrotZ`、`string` 也没有推翻 designs/22 中“不做 / 延后”的结论。
