# cleat-157 调用点类型反馈原型

- 里程碑：M18　依赖：cleat-156（避免 sigspec 调参改变同一批调用点的画像）　状态：完成
  （2026-10-23，本机 5 轮淘汰：不落运行时实现，不新增开关）
- 设计依据：[28 §2.3 / §3 / §7.2](../designs/28-hot-path-optimizations.md)、
  [notes M17 §4](../notes/r7rs-performance.md)、cleat-153 的量化收口

## 问题

cleat-153 已量出上限：接口调用 12.3 ns，具体类型提示 10.7 ns（净省约 **1.6 ns/次，5/5**）；
双态调用 13.9 ns（比接口调用慢约 **1.6 ns/次，5/5**）。也就是说，调用点一旦不是稳定单态，
反馈计数 / 查表的成本很可能吃掉全部收益。153 按纪律没有把这套机制落进默认路径。

M18 要做的是**原型**：先解决“开销模型是否能在真实负载里成立”，不是先铺完整反馈基础设施。

## 口径

原型不新增任何 `CLEAT_NO_OPT` / `CLEAT_OPT_*` 门。
如果真实负载证明净收益可声明，**直接默认启用**；
如果量不出收益，按 153 的纪律关闭这条路线并在本任务书记账，不为了“以后可试”留下默认关开关。
诊断用进程级事件只能在原型分支 / 非计时进程里开，不作为产品开关。

## 工作内容

1. 选择最小反馈载体：优先复用 M14 / M15 的 RuntimeSigTable / RuntimeSigKey 结构和 145 的具体类型守卫形态，
   不新建第二套计数表；单态探针先只覆盖接口调用点的接收者类型，不做全类型反馈。
2. 在原型里同时量三件事：计数增量、单态命中后的直调 / 直读收益、双态或多态时的守卫回落成本。
   探针结果必须参与数据依赖；IL 取证要确认守卫内没有通用宿主调用发射器的空值 / 返回包装税。
3. 建立淘汰条件：真实负载同轮配对中，收益中位扣除计数与表维护开销后不能过该项门槛，或双态项出现同向回退，即停手。
4. 若通过淘汰条件，再落完整语义：单态安装、守卫失败回落、类型分布变化、deftype 重定义、
   eval 单元生命周期、镜像 / 包加载边界、失效与并发读写。
5. A/B 覆盖 browse / peval / scheme / destruc 等接口密集项，以及 lattice / string / wc 等不受利项，
   防止分支位置或守卫链头回归。

## 验收

- 原型结论必须落在 notes：单态 / 双态 / 计数后净值、每项中位比值、同向轮数与门槛；
  通过或停手都要有明确裁决。
- 通过时：语义输出与改前逐字相同，真实负载整体不回退，受益项超过门槛；
  默认构建直接启用，无新开关。
- 停手时：不留半开的反馈计数路径，不留新开关；只保留设计 / 量化结论与可复现探针。
- 门禁与 154 相同；改 `src/clojure` 时重走种子不动点。

## 收口（2026-10-23，本机）

192.168.3.111 离线，按用户确认改为本机口径。`bench/r7rs/src/micro.cljc` 增加五格可复现探针：
调用点状态对象递增、单态 `isinst` 守卫 + 具体调用 / 接口回落、守卫 + 计数、双态两段守卫、
双态守卫 + 计数。计数状态是跨迭代可见的具体对象 mutable long 字段；该探针量的是“经状态对象维护反馈”
的可复现 Clojure 形状，不是把 +5.5 ns 解释成一次裸字段递增。复用函数入口签名表还要再付类型编码 /
查表 / 失效与并发维护。

默认路径 5 轮 `net-empty` ns/iter 中位：

| 形状 | 中位 | 相对基线 | 中位比值 | 同向轮数 |
|---|---:|---:|---:|---:|
| 接口直调 | 12.1 | — | — | — |
| 具体类型提示直调（理论上限） | 10.8 | -1.3 | x0.893 | 5/5 快 |
| 单态守卫（无计数） | 11.9 | -0.2 | x0.983 | 5/5 快 |
| 调用点计数 + 接口直调 | 17.6 | +5.5 | x1.446 | 5/5 慢 |
| 单态守卫 + 计数 | 16.7 | +4.6 | x1.374 | 5/5 慢 |
| 双态接口分派 | 13.3 | +1.2 / 接口 | x1.099 | 5/5 慢 |
| 双态两段守卫 | 14.5 | +1.2 / 双态 | x1.083 | 5/5 慢 |
| 双态两段守卫 + 计数 | 18.9 | +5.6 / 双态 | x1.414 | 5/5 慢 |

现有 145 的理想守卫直读臂另做 5 轮交替两臂（`CLEAT_OPT_ACCINLINE=1`，只作取证，不进产品开关口径）：
同臂接口直调中位 12.0、守卫 + 字段直读中位 14.3，**5/5 慢于接口直调**。IL 取证同时确认两点：
源级守卫方法臂会复用通用宿主调用发射器，守卫后仍有 `ldstr + ClojureStaticCalls.Instance`；
145 的专用直读路径则是 `isinst → castclass → ldfld`，没有 `Instance` / `RetObject` 税。也就是说，
即便取已有最干净的守卫直读形状，本轮也没有可拿收益；给任意接口方法补专用发射器没有必要继续。

复用判断：`RuntimeSigKey` 的 4 bit 类型码只登记 13 种固定常见类型；`MPair` 一类调用点接收者编码为
`Other=0`，而 `RuntimeSigTable.Slow` 对 key 0 不建特化。要支持任意接收者，必须再加调用点级
`Type → 小类型码` 映射 / 计数表，已经超出“薄复用”的范围。

**裁决**：单态理论上限 1.3 ns/次低于状态递增 5.5 ns/次；守卫后只剩 0.2 ns/次且 145 理想臂 5/5 为负，
双态再 +5.6 ns/次。按本任务淘汰条件在微探针层停手，不进入真实负载 A/B，不落默认实现，不新增开关。
本任务只改 bench 与文档，不改 `src/clojure`，种子链无需重走。
