## 问题

cleat-147 的净值探针已经把闭包成本分档：20M 次、5 个独立进程的本机中位下，

| 闭包形状 | 时间增量 | 分配增量 |
|---|---:|---:|
| 无捕获，相对空循环 | 17.290 ns/iter | 24 B/iter |
| 捕获静态变量，相对无捕获 | 12.613 ns/iter | 32 B/iter |
| 捕获 `volatile!`，相对无捕获 | 16.936 ns/iter | 56 B/iter |

peval 里每轮重建的 `ref_count$rc$fn__20` 曾占该项分配 17%。现在不再需要“分配画像估算”，
这条已经具备实现依据。

## 口径

本任务**默认全面启用，不新增 `CLEAT_NO_OPT=closurlift` 或其他新开关**。
改前 / 改后构建是 A/B 的对照方式；不能因为“能关回去”就把语义风险留给默认路径之外。

## 工作内容

1. 先做捕获组静态性统计：在 core、test_clojure、r7rs 与真实语料上统计无捕获、纯静态捕获、
   含 mutable / volatile / 局部可重绑定捕获的比例，确定首批提升面。
2. 无捕获闭包提升为模块级单例；初始化必须保持首次求值时机的语义，不把错误、宏展开副作用或 Var 解析提前。
3. 静态捕获闭包提升为常量闭包：只允许捕获编译期可证明不可变的值或静态 Var 引用；
   捕获 `volatile!`、mutable 字段、循环变量、可被 `set!` / 重定义影响的绑定一律不做。
4. 提升 `^:once` 闭包前单独核对 cleat-117 的字段清除与惰性序列持有生命周期；不为了少一次分配把根的生命周期拉长。
5. IL 取证：同一热点改后应不再出现每次迭代的 `newobj <fn>`；单例字段初始化只发生一次。
6. 需要动 `src/clojure` 时合并种子重生成；只动运行时也要跑完整门禁。

## 验收

- 语义用例覆盖：无捕获、静态捕获、`volatile!`、循环变量、`set!`、闭包跨返回后调用、
  同一源码位置在不同环境中出现、`^:once` / lazy-seq / delay、错误抛出时机；输出与改前逐字相同。
- 探针重测：无捕获与静态捕获的 ns/B 净值下降；`volatile!` 对照**不得被提升**，其数值保持基线量级。
- 真实 A/B 至少看 peval（主要受益）、dynamic、browse；同时看 array1 / lattice / string 不受利项不回退。
- 门禁与 154 相同；任何回退超过该项门槛都不进 main。

## 收口（2026-10-23）

- 已按任务书实现无捕获与纯编译期常量捕获的单例守卫，并重走种子不动点（stage2 == stage3，
  发射回种子逐字节一致）；但全量门禁立即否决了该机制。
- `tests/conformance/corpus.edn` 的 **fn identity / non-capturing fn** 五条新增失败：
  `(identical? (mk) (mk))` 期望 `false`、set / map / `distinct` 都必须把同一 `fn` 形式
  的多次求值当成不同对象、循环两轮也必须各得一个对象。这是 Clojure 的可见语义，不是实现细节；
  静态捕获只是缩小可提升集合，不能消除同一语义约束。
- 结论：**模块级单例与闭包身份语义互斥**。要保住每次求值的新对象就必须保留每轮分配，
  因此 147 量化出的 24 ~ 32 B/iter 不是可安全消除的成本。无捕获、静态捕获两档都不做提升；
  `volatile!` / 循环变量 / 可变捕获维持原不提升结论。
