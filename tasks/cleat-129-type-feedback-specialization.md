# cleat-129 类型反馈：特化单元的编译、安装、退回与失效

- 里程碑：M13　依赖：cleat-128　状态：关闭（2026-10-17，量化后不实现）
- 设计依据：[23 §2.2 ~ 2.4](../designs/23-type-specialization.md)

## 工作内容
1. 复用 eval 内联登记保存的 L0 子句；以观察到的类型作为形参的已知类型重新编译后段，生成 `invokeStaticSpec`，放进新的 eval 单元，后台线程编译。
2. 安装：函数类的静态字段保存特化入口（函数指针，或 Lcil 不支持 `calli` 时用生成接口的实例）；通用入口先检查"已安装且实参类型相符"再直调。
   Var 的值不变（`identical?`、元数据、with-redefs 不受影响）。
3. 退回与失效：类型不符走通用体；守卫失败超过阈值卸下特化、停止记录；Var 重定义后重新记录；每进程特化上限。
4. 第一版只特化"体内类型全部由形参类型决定"的函数（无需中途 bailout）；异常栈过滤覆盖特化方法。

## 验收标准
- cleat-128 统计出的受益函数前后耗时；微基准（实参实际是 double 而按用法猜了 long、无证据的宿主类型形参）接近有提示的版本。
- 开 / 关输出逐字相同；多线程调用同一函数时结果不变；基线、门禁、全量不变。

## 关闭记录

- cleat-128 的剖面开销在长跑里仍有约 0.72 ns / 次的静态检查残差；标准 bench/ 与 r7rs 常规文件执行没有任何触发，
  已有类型化入口 / 内联覆盖当前目标。为了零个已量化受益函数引入后台重编译、安装与失效的复杂度不成立。
- `CLEAT_NO_OPT=typefeedback` 保留，可在真实 eval 工作负载出现后重新统计触发面，再决定是否恢复本任务。
