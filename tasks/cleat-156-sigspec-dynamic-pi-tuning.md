# cleat-156 sigspec 对 dynamic / pi 的特化规则调优

- 里程碑：M18　依赖：cleat-155（避免在闭包分配噪声未消除前调参）　状态：未开始
- 设计依据：[28 §5 / §7.2](../designs/28-hot-path-optimizations.md)、
  [notes M17 §5](../notes/r7rs-performance.md)、cleat-152 的单开关归因

## 问题

cleat-152 已把 M14 / M15 的回退定位到 cleat-133 sigspec：同一构建下只关该开关时，
111 的 5 轮配对里 dynamic **x1.144（5/5 同向）**、pi **x1.126（5/5 同向）**、
mbrot x1.035（4/5 同向）；parsing x0.985 不可判定。全局 56 项仍证明 sigspec 有价值，
所以不能整体退开关，必须调候选 / 特化 / 逐出规则，把全局收益保住并消掉这两类回退。

旧 `git bisect` 的 first bad 只能代表当时的粗判据：按 151 的新逐格门槛补跑后，
83ee79f / 13b55d8 的边界都是 undecidable。不得把这一段说成“已证实的 commit 级 bisect”。

## 口径

本任务**不新增用户开关**。既有 `sigspec` 开关保留：它是 152 已经使用的单开关归因仪器；
新规则启用后不通过 `CLEAT_NO_OPT` 控制默认行为。
现有诊断环境（例如 `CLEAT_RTSPEC_DEBUG` / `CLEAT_RTSPEC_STATS`）可以用来取证，
但不作为性能臂的开关。

## 工作内容

1. 用同一构建采集 dynamic / pi / mbrot / parsing 与全局受益项的 sigspec 事件：
   候选命中、生成次数、阈值触发点、表项数、命中 / miss / alias / 逐出、特化体大小。
   事件采集只在诊断进程里跑，不把计数器放进计时段。
2. 对回退项定位成本来源：是候选筛选把低收益形状特化、快速 key 分支顺序不利、
   安装 / 重编译发生在热区、还是多签名互相逐出。逐项给出 IL / 事件证据。
3. 调整默认规则，候选方向包括但不限于：更保守的热度 / 门槛、调用路径静态类型已知时不再运行时特化、
   引用类型 key 的 specificity 与 alias 规则、表容量 / 逐出、生成体大小上限、安装时机避开热区。
   不按 benchmark 名单硬编码。
4. 每个规则改动都保留机制归因表：受回退项、受益项、中位比值、同向轮数、负载与门槛。
5. 与 149 §3 的退化路径健壮性一起检查：单开关关闭只用于诊断，不要求它继续代表可交付慢路径，
   但不得让诊断模式出现 100x 级未解释退化后仍不加记录。

## 验收

- 111 同轮配对至少 5 轮：dynamic 与 pi 的 sigspec 回退降到该项门槛以下，且不再与旧基线反向；
  全局 56 项对 JVM 几何平均不低于 M17 的 x1.596 附近（不得以两个单项修复换全局回退）。
- mbrot / parsing 单独成表；不可判定就写 undecidable，不硬凑结论。
- 特化语义用例：首次调用、阈值触发、类型变化、表满 / 逐出、Var 重定义、后台 / 同步编译、异常体；
  默认输出与语义基线一致。
- 门禁与 154 相同；改 `src/clojure` 时重走种子不动点。
