# 25 运行时引用类型签名特化：精确观察 + Tagged 静态决议

> 状态：**历史；运行时路径已由 cleat-170 删除**（2026-10-18 采纳首版）。本文是 [24](24-runtime-signature-specialization.md) 的后续。
> cleat-133 已经建立“编译期保留 L3 IR、`invoke` 入口观察、运行时按需生成、精确类型分发”的框架，
> 但生成器只接受 `Int64` / `Double`。cleat-134 把同一框架扩展到引用类型形参，不预生成组合。

## §1 结论

1. 不扩展 `L/D/O` 签名编码来表示任意 CLR 引用类型。签名仍只描述运行时入口的存储形式：
   `L` 是 `Int64`，`D` 是 `Double`，`O` 是对象引用。
2. 精确引用类型保存在 `RuntimeSigFn.Type[]`，作为分发 key；不进入静态签名字符串。
3. 运行时证明成功后，把引用形参在 L3 特化体中标成 `(Tagged ExactType p)`。
   已有的宿主调用静态决议器读取 `Tagged`，因此 `RT.aget` 可决议到 `int[]` 等类型化重载，
   后续算术按 cleat-112 加宽为 `long`，避免元素装箱。
4. 引用类型仍由 `RuntimeSigFn` 做精确 `GetType()` 检查。`null`、派生类型或其他签名都回退
   编译时通用函数；`TypedBailout` 也回退。

这样避免为 `String`、`Int32[]`、`PersistentVector`、任意用户类型发明签名字符或预生成组合。
签名 key 是运行时实际观察到的 `Type[]`，生成次数等于实际热签名数。

## §2 首版范围

| 项 | 决定 |
|---|---|
| 引用形参 | 任意非空精确引用 `Type`；候选体必须仍通过保守纯度检查 |
| 数值形参 | 继续 `Int64` / `Double`，并与引用形参混合 |
| 返回类型 | 首版仍只证明 `long` / `double`；引用返回暂不特化 |
| 安全宿主调用 | `RT.aget` / `RT.alength` / `RT.count`；先不接受 `aset` 等可变操作 |
| 生成时机 | 沿用 cleat-133：通用调用计数达到 16 后同步生成 |
| 表结构 | 沿用首版单签名 `__rtSpec`；其他签名回退通用函数 |

`aset` 虽然能让数组写入消除装箱，但 `TypedBailout` 后通用体重算可能重复执行副作用；
在建立效果分段或单执行证明前，保守不接受。

## §3 编译与运行时流程

1. 候选形状沿用 cleat-132 / 133：固定 arity、无闭包字段、无原始提示、递归体可证明、节点数受限。
   保守纯度检查新增无副作用的 `RT.aget` / `RT.alength` / `RT.count`。
2. 编译期仍不生成引用特化。若数值预生成候选为空，候选进入 `RuntimeSigEntry`。
3. 运行时观察参数：
   - `Int64` → `:l64`，`Double` → `:fl`；
   - 非空引用类型 → 签名 `O`，同时记录精确 `Type`；
   - 其他值类型或 `null` 不生成。
4. `spec-entry-try` 先按数值 + `O` 签名复制类型化体；随后把记录的引用形参标成
   `(Tagged ExactType p')`，再交给类型推断。只有返回类型和递归自调用实参都证明成立才继续。
5. 生成内存程序集。特化 IFn 的边界仍是对象；引用形参是本来就有的引用，不会额外装箱；
   `Int64` / `Double` 仍走 raw 局部。
6. `RuntimeSigFn` 保存精确 `Type[]`。类型完全一致才调用特化 IFn。

## §4 语义与回退

- 特化函数与通用函数捕获在同一个 `RuntimeSigFn` 中；`with-redefs` 后旧函数对象继续使用
  旧通用函数，新函数对象没有旧 `__rtSpec`。
- 精确类型不符、`null`、不同 arity 或 `TypedBailout` 都回退通用函数。
- 纯度检查失败、证明失败、生成异常一律返回 `nil`；入口禁用后续运行时生成。
- 首版不改变返回值表示：函数返回仍按编译时证明的 `long` / `double` 装箱。
  引用返回函数暂时不特化，避免 `Int32` / `Int64` 装箱表示变化。

## §5 验收

1. `Int32[]` 形参调用足够次数后生成特化，生成的 Lcil 中出现
   `RT.aget(Int32[], Int32)`；元素读取不再走通用 `Object` 路径。
2. `String` 形参可生成单参特化；`RT.count` 结果类型证明与通用语义一致。
3. 数值 + 引用混合形参可生成 `LDO` 一类混合签名。
4. 首签名建立后，`null`、其他引用类型、其他数值类型都回退通用函数。
5. 默认、`CLEAT_NO_OPT=sigspec`、`CLEAT_NO_OPT=typed` 的语义输出逐字相同。
6. Release 构建、SignatureSpecialization 专项、Core 全量与种子不动点通过。

## §6 后续

1. 支持引用返回值，并保持 Clojure 的数值表示协议。
2. 为 `aset` 建立效果分段或“放弃点前无副作用”的证明后再开放写入特化。
3. 首版单签名表扩展为多签名表，并接入可回收装载上下文批次。
4. 扩展保守可证明的宿主静态调用白名单，优先 `StringLength`、集合读取和只读属性。
