# 23 按参数类型特化：数组形参推测与运行时类型反馈

> 状态：**提案**（2026-10-16）。问题来源：运行 .clj 时能否根据调用参数的实际类型直接用非装箱的数据与指令
> （例如分析出是 `int[]` 就生成 `ldelem.i4` / `stelem.i4`）。本文是三层回答里的第 2、3 层；第 1 层（编译期已知类型时的原始值
> 与类型化数组访问）已有，`int[]` 等窄类型数组的缺口在 cleat-118 补上。任务 cleat-127 ~ 130（M13）。

## §0 现状

| 层次 | 机制 | 状态 |
|---|---|---|
| 1 编译期已知类型 | 类型提示、局部变量初值的宿主类型（cleat-112）、deftype 原始字段 → 原始算术、`RT.aget(long[], int)` 等类型化数组访问（cleat-106） | 已有；int[] / byte[] / short[] / float[] 仍走通用 `agetOnArray`（cleat-118 补） |
| 2 编译期推测 + 运行时检查 | 循环推测（cleat-103）、类型化入口（cleat-104）：按用法猜 long / double，入口检查实参类型，不符走通用体 | 数值已有；**数组形参没有**（本文 §1） |
| 3 运行时类型反馈 | 按实际调用时观察到的类型再编特化版本 | **没有**（本文 §2） |

.NET 的 JIT 帮不上：生成的 IL 里 Clojure 的值都是 object，JIT 不懂 Clojure 的数值语义，只能做守卫式去虚化（动态 PGO）。
特化必须在 cleat 编译器这一层做。

### 语义约束（两层共同）
- 结果逐字不变：读 `int[]` 元素得到 Int32（与 `agetOnArray` 的 `GetValue` 相同），参与 Clojure 算术时照常加宽成 long；
  `aset` 写窄类型数组照 intCast / byteCast 的范围检查抛异常；long 溢出照常抛 ArithmeticException。
- 特化只改变表示与指令，不改变求值顺序与副作用；类型不符时退回通用代码，不能有"跑了一半才发现类型不对"的重算（除非体是纯的，见 cleat-104 的规则）。
- 镜像 / 包的字节可确定（种子不动点）：§1 是纯编译期变换，可用于镜像；§2 只用于 eval（运行时编译），不进镜像。

## §1 第 2 层：数组形参推测（cleat-127）

### 候选
函数（或其循环）里某个**无提示的形参 p** 被当作数组用：`(aget p i)`、`(aset p i v)`、`(alength p)`，且这些用法在真正的循环里
（只在循环里值得多生成一份代码）。p 在函数体内不被 `set!`，循环里不被 recur 重新绑定成别的值（或只绑定成它自己）。

### 元素类型的证据
`(aget p i)` 本身看不出元素类型，按用法取证据，证据冲突或没有证据时不推测：
- `(aset p i v)` 里 v 的原始类型（:l64 → `long[]`，:fl → `double[]`，其余 → `object[]`）；
- `(aget p i)` 的结果进入原始算术 → `long[]` / `double[]`（按算术的推断类型）；进入通用用途 → `object[]`；
- 调用点的证据（同一单元里以已知类型的数组调用它，cleat-110 的已知调用）优先于体内证据。

最多推测 **两种**元素类型（例如 `long[]` 与 `object[]`），超过时不推测。

### 生成（实现时改为循环推测，见 cleat-127）
> 实际实现挂在循环推测（cleat-103）上：对最内层循环外绑定、循环里当数组用的变量做 `isinst T[]` 检查，快份循环里把它换成带
> `Tagged T[]` 标注的绑定，数组访问由 cleat-106 的静态决议选到类型化重载。不要求函数是纯的，闭包里的循环也适用；下面的入口方案作为备选保留。

沿用 cleat-104 的类型化入口框架，签名字符扩展数组类型（例如 `J` = `long[]`、`D[` = `double[]`、`O[` = `object[]`、`I[` = `int[]`）：
1. 通用入口在原有检查之前 `isinst T[]`（一维数组是 sealed 类型，一次方法表比较）→ 转调 `invokeStaticTyped_<sig>`；
2. 类型化体里 p 是 `T[]` 局部变量：`aget` / `aset` / `alength` 直接用 `ldelem` / `stelem` / `ldlen`（窄类型按 §0 的语义加宽 / 检查）；
3. 不符时走通用体，**不需要 bailout**：数组的类型在进入时就确定，且 p 不会在体内变成别的数组。

### 验收
- 无提示的数组循环微基准（`long-array` / `double-array` / `object-array` / `int-array` 各一）接近有提示的版本；
- r7rs 的移植大多已有 `^objects` 提示：另做一组去掉提示的变体对照；`data/array_semantics.clj` 开 / 关逐字相同；
- 开关 `CLEAT_NO_OPT=arrayspec`；种子不动点（镜像里的函数也会用到）。

## §2 第 3 层：运行时类型反馈特化（cleat-128、129）

只用于 eval 单元（运行时编译本来就在发生）。思路与 JVM / .NET 的分层 JIT 相同，只是特化的依据是 Clojure 层的值类型。

### 2.1 剖面记录（cleat-128）
- **候选函数**：能做类型化入口的体（纯运算、1 ~ 4 个形参，cleat-104 的条件），但编译期推测不成立或没有推测
  （例如实参实际是 double 而按用法猜了 long、或形参是无证据的数组 / 其他宿主类型）。
- **记录**：通用入口里对每个形参记"方法表指针 + 计数"到函数类的静态字段（每个形参一个槽，看到第二种类型就标为多态）；
  记录本身是几条普通指令，不分配。只在调用计数达到阈值前记录（之后关闭，避免长期开销）。
- **触发**：调用计数或循环回边计数到阈值（例如 1000 次调用），且每个形参单态 → 把该函数排进特化队列。
- 本任务先只做记录与触发，并量化：记录的开销（对 fib、tak 一类调用密集的函数）、在 r7rs 与 bench/ 上有多少函数会被触发、
  各形参观察到的类型分布。数字决定是否进入 cleat-129。

### 2.2 特化与安装（cleat-129）
- **IR 保留**：编译时为候选函数保留子句的 L0（cleat-116 的 eval 内联登记已经存 fasl 的 L0 子句，复用同一份）。
- **编译**：用观察到的类型作为形参的**已知类型**（不是推测）重新跑编译器的后段，生成 `invokeStaticSpec`（原始类型的形参与结果），
  放进一个新的 eval 单元；后台线程编译，不阻塞调用方。
- **安装**：函数类有一个静态字段保存特化入口（函数指针或一个生成的接口实例）；通用入口在记录之前先检查"特化已安装且实参类型相符" →
  直接调特化版本。Var 的值（函数对象）不变，`identical?`、元数据、with-redefs 都不受影响。Lcil 若不支持 `calli`，用生成的接口
  `ISpec_<sig>` 的单实现类实例代替函数指针。
- **退回**：实参类型不符就走通用体（与类型化入口相同）。特化体内若有"类型来自未知调用的结果"的位置，只允许出现在纯体里
  （可整体重算，沿用 TypedBailout）；第一版干脆不特化这类函数。
- **失效**：Var 被重定义时新函数类重新记录；同一函数的特化失败（守卫不符）超过阈值时卸下特化并停止记录（多态）。
- **上限**：每个进程最多特化 N 个函数（不可回收的装载上下文里的程序集不释放，见 cleat-114），超过后不再特化。

### 2.3 与已有机制的关系
- 与类型化入口（cleat-104）、循环推测（cleat-103）共用签名、代码生成与入口检查；特化只是"把推测换成观察"。
- 与已知调用 / 内联（cleat-110 / 116）：调用点内联了小函数时不需要特化；特化针对没有被内联、调用密集的函数。
- 与分层编译（cleat-114）：特化版本同样装进不可回收的 ALC，享受 .NET 的分层与 PGO。

### 2.4 风险
- 编译延迟与内存：特化单元每个约几 KB，编译约毫秒级；用后台线程与上限控制。
- 不确定性：同一程序在不同输入下特化不同，性能可能随输入波动；语义不变，可用 `CLEAT_NO_OPT=typefeedback` 关闭对照。
- 调试：异常栈里出现特化方法（`invokeStaticSpec`）；栈过滤与 `CLEAT_TRACE_ERRORS` 的规则要覆盖。
- 线程：剖面记录允许数据竞争（只影响是否特化，不影响结果）；安装用 volatile 写。
